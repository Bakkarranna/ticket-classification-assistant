# Evaluation report

- Development/reference tickets: 100
- Fixed held-out evaluation tickets: 20
- Categories: 10
- Class balance: 10 development and 2 evaluation tickets per category.

**Important:** v1/v2 are deterministic local mock/fixture outputs, not hosted LLM results. The figures demonstrate a reproducible comparison pipeline only. Similarity confidence is not a calibrated probability.

## Prompt v2 errors

No v2 classification errors occurred on this small, deliberately balanced evaluation set. This does not establish production accuracy; the test set is small and close to the category definitions.

## Summary quality inspection
Summaries are extractive: they retain the submitted ticket wording, normalize it to one sentence, and truncate long text. This minimizes unsupported claims, but it is not abstractive summarization and may preserve awkward wording. No completion/action language is generated by the local mock.

## At least three limitations / likely failure modes
1. **Vocabulary mismatch:** a ticket phrased with terms absent from the keyword list or category examples may receive a weak or incorrect label.
2. **Overlapping services:** LMS assignments, student portal registration, and library database login can share terms such as “portal”, “login”, or “account”; context is needed to disambiguate.
3. **Small evaluation set:** two examples per category are not enough to estimate real-world performance or represent varied writing styles.
4. **Mock prompt evaluation:** prompt v1/v2 are local approximations, not actual LLM calls; no claim about hosted model performance is made.
5. **Summary quality:** extractive summaries can be repetitive and may not compress the issue into a polished help-desk note.
